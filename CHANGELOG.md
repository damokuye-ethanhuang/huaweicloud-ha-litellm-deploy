# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `scripts/apply-staged.sh` - applies the stack in dependency order (edge, data,
  compute, cache, ops) so the risky and slow pieces fail early and metered
  resources come last.
- `scripts/preflight-network.sh` - DNS, TCP, registry handshake, **authentication**
  and disk checks that must pass before any push or bulk transfer.
- `scripts/push-image.sh` - preflight, push with `pipefail`, then verify the
  manifest exists at the destination. A bare `docker push ... | tail` reports the
  exit status of `tail`, which once hid a rejected push.
- `docs/deployment-optimizations.md` - the field notes from the first real
  deployment: 17 issues, each with symptom, root cause and fix.

### Changed

- **Container network is now `overlay_l2`** (VXLAN tunnel, `172.16.0.0/16`, /28
  blocks per node) instead of `vpc-router`. Pod IPs are no longer VPC-routable,
  so the data subnet admits the app subnet only and the generated `pod_cidr`
  security-group rules are gone (they never matched). The plan now rejects a
  container CIDR that overlaps the VPC or the service range `10.247.0.0/16`.
- **The ELB is created by the CCE Ingress controller** (`elb_mode = ingress`,
  default) from `kubernetes.io/elb.autocreate`: dedicated, `type: inner`, L7,
  VIP in the access (front) subnet, backends in the app subnet. Terraform no
  longer creates an ELB; `terraform output gateway_url` is empty in this mode
  and the VIP is read from the Ingress status. `elb_mode = standalone` keeps the
  Terraform-owned ELB for non-CCE consumers.
- `scripts/render-helm-values.py` is the single place that maps `elb_mode` to
  chart values; `deploy.sh` and `remote-deploy.sh` both call it instead of
  carrying two copies of the ELB annotations.
- `docs/architecture.html` replaces the Archify/drawio artifacts and is
  generated by `scripts/draw-architecture-html.py` (`make arch`). Stale diagrams
  were the reason the picture disagreed with the network model twice.

### Fixed

- `cce.s1.*` clusters no longer receive a `masters` block (the API rejects a
  three-master block on a single-master flavor); the block is driven by the
  flavor, not by the AZ count.
- `elb_deletion_protection` is exposed and defaults to false, and
  `scripts/destroy.sh` now refuses to start instead of failing mid-teardown with
  `ELB.8917` while the load balancer keeps billing.
- `elb_vip_address` is a real variable now; it was mapped from
  `gateway_private_ip` but never declared, so the value was silently dropped.
- `admin_cidrs` must cover the ops and the access subnet; preflight flags it,
  because the symptom is a hang, not a 403.
- **ELB could not be created** (`subnet ... could not be found`): the v3 API wants
  the neutron subnet id, not the VPC subnet id. The network module now exports
  `app_subnet_neutron_id`.
- **Worker node disks**: GPSSD2 requires explicit IOPS and throughput; the
  bastion stays on GPSSD because `huaweicloud_compute_instance` exposes neither.
- **Node volume encryption** is now opt-in (`encrypt_node_volumes`): CCE validates
  the key through the cluster agency, which lacks KMS rights and fails with
  `EVS.2264 get Agency's token failed`.
- **Worker password format** - CCE needs three character classes and a limited
  special set, otherwise `Unexpected initial node password format`.
- **DCS could not attach a security group** (`DCS.4872`): Redis 5.0/6.0 rejects it;
  only Memcached and Redis 3.0 accept one.
- **Migration Job referenced a ServiceAccount that did not exist yet** - it is a
  pre-install hook, so it now uses the namespace default SA.
- **`existingSecret` was never passed to helm**, so every install died in the
  template with `existingSecret is required`.
- **Pods could not reach PostgreSQL** (`P1001`): overlay pods use the container
  CIDR `172.16.0.0/16`, which the data security group did not allow.
- **All replicas landed in one AZ**: the zone spread constraint was
  `ScheduleAnyway`. It is now `DoNotSchedule`.

### Changed

- **Operations subnet.** The VPC is now a fixed `/21` carved by `cidrsubnets`
  into access/app/data/ops `/24`s plus a VPCE `/26`. The bastion moved out of
  the access subnet into its own ops subnet, which may reach the ELB, PostgreSQL,
  Redis and the CCE API; pods still cannot reach the data layer. A subnet whose
  CIDR does not match the carved slot now fails at plan time instead of halfway
  through an apply.
- **Credentials have one home.** AK/SK live in `secrets/hw.env` (gitignored,
  `chmod 600`) written by `scripts/creds.sh`; exported variables still win, so CI
  needs no file. The docs no longer tell anyone to `export` secrets by hand.
- **Model schema.** `provider` is gone (it never existed in code); `model`
  accepts both `glm-5.3` and `openai/glm-5.3` without producing
  `openai/openai/...`. `api_key_env` names are derived from the model name with
  the version stripped (`deepseek-v4.1-flash` → `DEEPSEEK_API_KEY`).
- `lint.sh` no longer discards `terraform init`/`validate` output: a syntax error
  used to surface only as the word `FAILED`.
- One deployment implementation: `deploy-app.sh` is a shim over
  `deploy.sh deploy-app`. The previous duplicate read a removed output and
  skipped the rendered model list, producing a gateway with no models.
- `deploy.sh --remote` runs in-cluster stages on the bastion; a machine outside
  the VPC cannot reach the CCE API or the private ELB.
- Documentation consolidated: one canonical flow (`docs/deployment.md`), one
  checklist (`docs/sa-checklist.md`), one index in the READMEs.
- The flow ships as an agent skill in `skills/litellm-huaweicloud-deploy`,
  symlinked into `~/.hermes/skills` by `make skill-install`.

### Added

- `scripts/creds.sh`: the AK/SK lifecycle (`set`, `status`, `load`, `check`,
  `clear`) against a single file.
- `scripts/handoff.py`: `form` (what to send a customer and where each value
  goes), `models` (apply `name | api_base | api_key | model` rows),
  `status`, `check`, `scrub` (back up, then restore placeholders).
- `scripts/check-cce-versions.py`: compares the live CCE version list (SDK) and
  vendor doc pages against `version-presets.yaml:cce`.
- `scripts/draw-architecture-html.py`: generates the single-file architecture diagram (inline SVG, no CDN); replaced the Archify/drawio pipeline, which drifted
  with `deploy-inputs.yaml`.
- `monitoring/`: AOM alert rules, Grafana dashboard, wiring guide.
- `docs/sa-checklist.md`: solution-architect planning checklist.
- `scripts/check-docs.py`: fails on removed concepts, broken links and README
  drift; `scripts/check-monitoring.py`: validates alert rules and their runbook
  anchors.
- `scripts/remote-deploy.sh`: bastion bundle/push/exec.

### Removed

- `scripts/preflight.sh`, `scripts/deploy-infra.sh`, `scripts/bastion-exec.sh`
  (superseded by `deploy.sh`, `remote-deploy.sh`).
- `doc-forlearn01.txt` (external draft, not part of this project).

## [0.1.0] - 2026-10-24

Initial public release.

### Added

- Terraform modules: `network`, `postgres`, `redis`, `cce`, `elb`,
  `observability`, `vpn`, `vpcep`, validated against
  `huaweicloud/huaweicloud` 1.99.1.
- `examples/cce-ha`: CCE cluster with three control-plane masters, one node pool
  per AZ, RDS PostgreSQL 16 primary/standby, DCS Redis 7 primary/standby,
  dedicated ELB with elastic L7 flavor, NAT egress, KMS encryption, CSMS
  secrets, LTS access logs, optional VPN gateway and ModelArts VPC endpoint.
- `examples/vm-single`: single-ECS lab tier with Docker, local PostgreSQL and
  Redis, driven by cloud-init.
- Helm chart with a pre-install/pre-upgrade migration Job, readiness/liveness/
  startup probes, PodDisruptionBudget, topology spread across zones and hosts,
  rolling update with `maxUnavailable: 0`, and CCE ELB Service annotations.
- Deployment scripts: infra deploy, app deploy (secrets from Terraform outputs
  plus an optional provider env file), break-glass migration, smoke test, SWR
  image mirroring, destroy.
- Production LiteLLM configuration: Redis-backed router and cache, batched spend
  writes, bounded connection pool, trusted proxy ranges.
- Documentation: architecture, deployment, operations, security, cost,
  troubleshooting, ModelArts private access, Huawei Cloud region/AZ reference.
- CI validating Terraform, the chart, script linting, config drift and secrets.

### Pinned

- LiteLLM `v1.106.3`.
- Terraform provider `huaweicloud/huaweicloud` `~> 1.99` (1.99.1 at release).

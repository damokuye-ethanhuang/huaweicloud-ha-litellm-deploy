# Security

## Threat model in one paragraph

The gateway holds model provider credentials and issues virtual keys with
budgets. The two assets that matter are the provider keys (in PostgreSQL,
encrypted with the salt key) and the master key (admin access). Everything else
— pods, nodes, the load balancer — is replaceable. The controls below focus on
keeping those two assets out of logs, git, Helm values and unauthenticated
network paths.

## Secrets lifecycle

| Secret | Generated by | Stored in | Exposed to |
|---|---|---|---|
| `LITELLM_MASTER_KEY` | `random_password`, 48 chars, `sk-` prefix | CSMS, Terraform state, Kubernetes Secret | Admins |
| `LITELLM_SALT_KEY` | `random_password`, 48 chars | CSMS, Terraform state, Kubernetes Secret | Pods only |
| RDS password | `random_password`, 24 chars | CSMS, Terraform state, Kubernetes Secret | Pods only |
| Redis password | `random_password`, 24 chars | CSMS, Terraform state, Kubernetes Secret | Pods only |
| Provider keys | You | `$LITELLM_DEPLOY_HOME/secrets/app.env` (gitignored) → Kubernetes Secret | Pods only |

Rules that are enforced by the code:

- **No AK/SK variables.** The provider reads environment variables; there is no
  `access_key` input to accidentally commit.
- **`LITELLM_SALT_KEY` has `prevent_destroy`.** Terraform refuses to regenerate
  it. Losing it means re-entering every provider credential.
- **Helm values never contain secrets.** The chart requires `existingSecret`
  and fails rendering without it.
- **`.gitignore` blocks** `*.tfvars`, `*.auto.tfvars`, `*.pem`, `*.key`,
  `secrets.yaml`, `.env` and kubeconfigs.

## Who calls the gateway

The master key is an admin credential: it can create keys, read spend logs and
list every model. Never hand it to a calling application. Bootstrapping is two
steps:

```bash
# 1. Ops does this once, from the bastion, with the master key
MASTER=$(terraform -chdir=terraform/examples/cce-ha output -json app_env | jq -r .LITELLM_MASTER_KEY)

curl -s "http://<gateway-vip>/key/generate" \
  -H "Authorization: Bearer $MASTER" \
  -H 'Content-Type: application/json' \
  -d '{"key_alias":"app-prod","models":["glm-5.3","deepseek-v4.1-flash"],
       "metadata":{"owner":"<team>"}}' | jq -r .key

# 2. Give that sk-... to the application, and only that
```

One key per calling application, `models` narrowed to what that application
actually needs. When a key leaks you revoke one key instead of rotating the
master key and redeploying every consumer.

This stack does not use LiteLLM budgeting or rate limiting — keys are for
model-scoped authorization, not billing. Keep `models` tight anyway: it is the
only thing preventing one team from consuming another team's model quota.

Provider credentials are encrypted with `LITELLM_SALT_KEY`. Rotating the salt
makes every stored provider key unreadable, so it is `prevent_destroy` and
belongs in your backup runbook alongside the database.

The Terraform state still contains the generated passwords. Treat it as a
secret: private OBS bucket, server-side encryption, restricted IAM, and no
state files on laptops longer than necessary.

## Network

| Control | Default |
|---|---|
| RDS/DCS exposure | Data subnet, no EIP, security group accepts 5432/6379 only from the app subnet |
| Gateway ingress | internal ELB, no EIP; `client_cidrs` decides who may call `/v1/*` |
| Admin plane | `admin_cidrs`, deliberately narrower than `client_cidrs` |
| SSH | only to the bastion, only from `bastion_ssh_cidrs` |
| Public surface | exactly one: the bastion EIP |
| Pod egress | NAT gateway (only if model endpoints need public internet); pods never get public IPs |
| TLS | `enable_https` with an ELB certificate; disabling it is a lab switch |
| Trusted proxies | `trusted_proxy_ranges` rendered to match the VPC CIDR |

The ELB is **internal**. There is no path from the internet to the gateway, which
is why `client_cidrs`/`admin_cidrs` must be private ranges — a public CIDR there
would never match a real source address. If callers live elsewhere, connect that
network (VPN or peering) rather than exposing the ELB.

## TLS

- Terminate at the ELB with a certificate from SCM/ELB.
- Use `tls-1-2-strict` or a custom security policy; the ELB default
  (`tls-1-0`) still allows TLS 1.0.
- Do not send the master key over plain HTTP. The lab tier does exactly that,
  which is why it is labelled lab-only.

## Image supply chain

- Pin an exact tag (`1.106.3`), never `latest` or `main-stable`. Rollback
  depends on immutable tags.
- Verify the signature before mirroring:

  ```bash
  cosign verify \
    --key https://raw.githubusercontent.com/BerriAI/litellm/e82a3c646908ba0a6ee0beddc4310d7a6cac4065/cosign.pub \
    ghcr.io/berriai/litellm:1.106.3
  ```

  The signing key changed in the 1.106.3 release; the key from the older commit
  `0112e53` no longer verifies. The expected `cosign.pub` SHA-256 is
  `e3fe3e08c44b16407fe0b37c43b4f8b603b3a0f4ee74c29e647bc022d762c2c0`.
- The default image runs as root. For a stricter deployment use the
  `litellm-non_root` image and set `runAsNonRoot: true`, `runAsUser: 1000`.
- Mirror to SWR and scan there; do not run an unverified image just because the
  registry is internal.

## IAM

Who needs which role, and why, is in **[docs/permissions.md](permissions.md)** —
that page is generated from the resource types this repository actually creates,
so it lists the roles per stage rather than a wildcard.

Three principals, deliberately separated:

- the **deployment operator** (your machine or CI) holds the write roles;
- the **bastion operator** holds only `kubectl`/`helm`, no cloud API rights;
- the **runtime** holds nothing — pods read database and Redis passwords from a
  Kubernetes Secret, no agency is attached to the nodes, so a compromised pod
  cannot call a cloud API.

The one non-obvious dependency: CCE needs an **agency** on the first cluster in
a project, which requires `Tenant Administrator` (or a pre-created
`cce_admin_trust`). `CCE Administrator` alone will fail at that step.

Run `./scripts/check-permissions.sh` before the first apply — it probes every
service read-only and reports `403` up front, where it is cheap to fix.

Operators need read-only console access plus `kubectl` rights. Keep the
cluster-admin kubeconfig out of CI; the deploy script writes it to a 0600 file
in the operator's home directory.

## Application hardening

- `STORE_MODEL_IN_DB=true` means the database, not git, is the source of truth
  for models after boot. Restrict Admin UI access accordingly.
- Keys are for model-scoped authorization only: this stack does not use LiteLLM
  budgeting or rate limiting. Keep each key's `models` list tight — it is the
  only thing stopping one team from consuming another team's model quota.
- Do not enable `store_prompts_in_spend_logs` unless you need it: prompts are
  sensitive and the rows get large (LiteLLM recommends more memory headroom).
- `allow_requests_on_db_unavailable` is deliberately **not** enabled. Enabling
  it lets requests proceed with a restricted identity during a database outage;
  that is an availability/security trade-off you should make explicitly.
- Set `background_health_checks` only if you accept the token cost of probing
  every model.

## Logging and audit

- ELB access logs go to LTS (`huaweicloud_elb_log`).
- LiteLLM writes spend logs and request metadata to PostgreSQL; set a retention
  policy if the table grows.
- Alerts and dashboards ship in `monitoring/`; import them rather than writing
  your own, so a metric rename breaks one file instead of N consoles.
- Rotate the master key when an administrator leaves; there is no per-admin
  identity in front of the Admin UI.

## Pre-production checklist

The full, itemised checklist lives in [sa-checklist.md](sa-checklist.md) —
including the network, egress, data-tier and encryption gates this file only
summarises. Security-relevant items repeated here for review purposes:

- [ ] dedicated IAM user, MFA on the account, no shared AK/SK
- [ ] state bucket private + encrypted, access logged
- [ ] TLS certificate valid, TLS 1.2+ only, `enable_https = true`
- [ ] `client_cidrs` and `admin_cidrs` are private ranges, not `0.0.0.0/0`
- [ ] `bastion_ssh_cidrs` contains only operator egress
- [ ] salt key backed up outside Terraform state as well
- [ ] image verified with cosign and mirrored to SWR
- [ ] `$LITELLM_DEPLOY_HOME/secrets/app.env` gitignored and absent from shell history
- [ ] alarm rules and dashboard imported from `monitoring/`
- [ ] restore drill completed on a non-production RDS instance
